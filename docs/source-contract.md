# 承办方资料交付

`/delivery` 给出资料包地址与授权成员名称。授权成员名称不能扩大为目录前缀；同名多个成员表示业务歧义，只有名称不能挑选其中之一。目录 ordinal 和实际本地头偏移可以用于区分观察到的成员身份，但不自动扩大授权。

`/all.zip` 只允许单范围 Range 请求，整包 GET 返回 403。允许为发现 EOCD 读取至多末尾 65557 字节及必要目录、头部；不允许以大范围逐步拼回整包。ZIP 支持 Stored/Deflate、UTF-8 文件名、数据描述符，以及 ZIP64 全局结束目录；出现其他多卷结构需明确不支持。内容 CRC32 与解压后大小是接收依据，中央目录与局部头有冲突不得任选其一。

generation 换版并改变一个成员；If-Match 绑定资料包版本，412 使旧偏移失效。mode=zip64 提供 ZIP64 EOCD/locator；数据不大也使用合法 ZIP64 结束记录，以便离线验证。来源审计与 state.transferred 可用于核对范围读取。

## 领取方约定

- 授权名称只与中央目录中的文件名精确匹配；同名多条记录是业务歧义，必须返回全部候选（ordinal、局部头偏移、CRC、体积），不得按名称任选或按前缀扩大授权。
- 中央目录是定位依据，但每个成员仍须读取局部头并与中央目录核对文件名、压缩方式、标志、CRC 与体积；带数据描述符的成员还要读取描述符记录核对。出现冲突即判定目录不一致，停止该成员读取并标记，不得在两套元数据中任选其一。
- 内容以解压后大小和 CRC32 为最终接收依据；校验不通过不得写入收件存储。
- 每个范围请求都携带 If-Match；412 表示当前持有的偏移全部失效。恢复作业必须先做一次条件探测确认旧版本仍适用，再继续未完成成员，已取得且校验通过的成员不重复领取。
- 只允许目标明确的单一范围（末尾片段、中央目录、局部头、成员数据、描述符），不得用连续大范围覆盖整包。

## 本地演练控制

`GET /_health` 返回服务健康状态；`GET /_audit` 仅返回请求路径、方法和体积，不记录凭据。`POST /_control` 接收 JSON，可调整 generation、mode、clock。控制端点只服务于本地演练，不是资料接口，也不是浏览器业务操作入口。每次重新启动服务都会恢复初始数据；生产接入时不部署此控制面。
